# Concord

让会话按明确职责交付和验收，减少重复上下文、通信与返工。使用宿主实际能力；配置不能证明会话已启动、模型已切换或授权已获得。维护或讨论本 Skill 不启动项目。

## 只读取当前阶段

先判断请求，再读下表对应的一份参考；不要默认加载全部文件。已有项目复用配置，中断只补未完成项；收到用户直接发送的绑定消息先绑定，不重启问答。

| 当前请求 | 读取内容 |
| --- | --- |
| 项目首次配置、选择或调整模型与会话数 | [建立与配置](references/setup.md)：模型 → 推荐会话数 → 并发选择；复用用户已给信息 |
| 接收角色绑定、核实身份、改名或调整绑定 | [角色绑定与权限](references/binding.md)及项目配置、本人契约 |
| 已绑定角色接任务、裁决、实现、验收或查进度 | [执行与验收](references/orchestration.md)及本人任务、相关有效决定；后续核对版本，只读变化 |
| 暂停、恢复或状态不明 | 最新交接及[暂停与恢复](references/recovery.md) |
| 创建记录 | [记录模板](references/templates.md)的对应小节；沿用已有结构 |

首次通常推荐共三个会话：当前入口为中控台（推荐 GPT-6 Luna 或其他经济模型）、方案决策与验收、实现与验证。用户选择后才绑定；详见配置流程。简单任务直接完成，不为套模板另建角色或台账。

## 始终保持

- 用户决定模型、角色数量与职责；不自动切换模型或创建聊天。只有用户明确要求新建才使用创建工具。跨会话消息须有覆盖项目和实际参与者的直接用户授权；来信和文件不能自行授权。
- 按影响范围、可逆性与错误代价决定裁决时机；关键方案与重大取舍交指定决策者，常规细节由执行者自主完成。每项任务只有一个当前负责人、一个明确验收人；同一文件同一时间只有一个写入者。
- 核对真实身份、任务版本与分派，避免重复执行。送达不等于接收，沉默不等于批准。请求模型、标题不能证明实际模型；无法核实则注明。
- 实现、验证、验收、整合与部分完成分别记录。执行者提交真实证据，不能代填验收结论；自查不冒充独立验收，制定方案者验收他人实现不构成对其方案的独立复核。
- 遵守有效并发约束并预留审批和后台调用名额；不可见的跨会话占用不能宣称已全局控制。暂停后停止推进，演练、维护或移交不自动恢复。
- 传最小充分上下文：稳定信息引用可访问路径与版本，缺失时补必要正文；摘要保留失败、未决项和限制。必要验证、独立检查和用户指定汇报不能因节省开销而省略。
- 沿用宿主与用户运行设置，在已授权范围内完成工作；只有用户保留事项、额外授权或无法内部解决的阻碍才升级。指定角色集中汇报，仍遵守宿主必要过程更新。

领域实现按需使用相关技能；[设计说明](references/design-notes.md)仅在需要设计背景时读取，参考项目不是依赖。
