# 执行与验收

用于接收分派、内部裁决、实现、验证、交付和整合。首次绑定读取项目配置、本人契约、当前任务及相关生效决定。后续先核对权威记录的当前配置/任务版本、分派序号和暂停状态，只读变化及其影响；沿用已有台账，不为增量读取新建系统。身份、版本或证据失配以及中断恢复时重读相关原文，不能用记忆中的旧版本证明未变化。暂停项目仅执行用户明确授权的例外范围。

## 1. 接收有效任务

任务应明确ID、规格版本、分派序号、执行负责人、验收人、工程与基线、可写范围、依赖及放行条件、预期产物和验收标准。规格缺口影响行为或依赖未满足时先提交事实、影响与建议，不自行补猜。

核对当前分派和文件归属后真实回执 `ACCEPT`，可并入首条进展；短任务可与交付合发，但须明确已接收及其任务/版本/序号。若调度依赖接收确认或任务耗时较长则先回执。收到同一任务/版本/序号的重复消息时引用已有结果，不重启任务、服务或扣除资源；旧分派不能覆盖新状态。送达、未回复和超时都不代表接收或批准。

分派和启动模型工作前核对配置中的并发选择、统计范围及已有约束，给可见审批和后台模型调用预留名额，超额任务排队；不额外设置项目上限仍沿用原有限制。跨渠道共享额度或其他会话占用无法核实时保守安排，并说明不能保证全局实时计数；配置不是跨进程硬限流器。

推荐状态流：就绪 → 已分派 → 执行中 → 待验收 → 已验收 → 已整合。只有确需裁决时才等待裁决；退回记需修复，等待原因和覆盖范围单列。无需整合的任务以验收为终点，暂停见[恢复规则](recovery.md)。

## 2. 沟通与裁决

消息保留项目、类型、发送与接收身份、任务ID、规格版本/分派序号、权威路径/版本及所需动作；真实传输回执可作为消息ID。类型使用 `ASSIGN`、`ACCEPT`、`QUESTION`、`DECISION`、`DELIVER`、`REVIEW`、`HANDOFF`。正文只写结论、变化或阻碍，细节引用记录；一条消息可逐项承载同批多个任务，但不省略各项身份、结果与责任人。模板见[记录模板](templates.md)。

发送前区分只读查看与会触发模型工作的消息工具；对后者写“无需回复”仍可能启动新轮次。仅在需要接收方行动、解除依赖或完成用户指定的结果交付时发送。没有后续动作的终态结论留在验收人可查的结果或有权维护的既有记录中，不为礼貌确认唤醒已结束的角色；指定汇报和必要状态传递不能省略。

有独立中控时，由它接收用户指令、维护有效任务与汇总进度，技术方案及行为裁决交方案负责人，实现验收交验收负责人；中控不代填决定或验收结论。用户询问进度时核对最新可用记录，标明状态来源和核对时点；中控结束轮次不代表停止项目，也不要求通过持续轮询保持在线。

### 按角色传递必要信息

- 中控读取任务状态、变化、阻碍、下一步及证据位置，按需查看细节；不默认读取完整实现历史、原始日志或重复技术分析。
- 在用户已授权的项目与参与者范围内，实现者直接向决策者提交必要问题、方案建议和交付，决策者直接返回决定或验收结果。中控收到影响分派、依赖、范围或用户汇报的变化即可，不逐条转述或抄送每次往返。缺少直接沟通授权或工具能力时，沿用已选的中控或用户转交方式。
- 有效决定和证据保存一次，消息引用其路径、版本和结论。接收方只补读相关范围；无法访问、证据失配或风险需要时读原文，不用短摘要代替必要核查。
- 相关问题合并提交；方案在关键节点裁决，交付按可验收成果合批。模型能力不足或风险升高时按已有策略升级，不为省钱强制先让便宜模型试错。

### 按任务风险决定何时裁决

依据影响范围、可逆性、证据与错误代价判断，不按代码行数或提示词长短分级，也不要求每项任务填写风险表。

| 情况 | 执行方式 |
| --- | --- |
| 范围清楚、局部可逆，遵循有效规格与接口 | 执行者自主完成并验证，例如局部修复、既定接口内实现、相关测试和文档；无需先请决策者批准，仍按既定标准验收 |
| 原因未明、证据不足，尚不能确定影响 | 执行者先做已授权的调查和可逆验证，带证据与建议提问；涉及改变行为或扩大影响的部分等待裁决，其他已就绪的独立工作可继续 |
| 改变公共接口、跨模块设计、兼容承诺、权限边界，涉及难以撤回的数据变更、重大依赖或需求冲突 | 在实施相关变更前交指定决策者确定方向与约束；技术裁决不替代用户保留的授权 |

已有有效决定覆盖当前选择时直接沿用，不重复审批。实施中发现风险升高、原假设失效或超出契约时重新评估，只暂停受影响部分；不能把关键变更拆小后绕过裁决。指定角色权限及用户要求优先，不因低风险取消必要验证或独立验收。

提问集中说明：问题、关键证据、建议方案及影响、需要决定什么、等待期间可继续什么；信息不足时标明未知，不为凑选项编造方案。裁决者返回选定方向、约束和放行条件，将有效决定写回规格；实质变更提高规格版本，通知受影响负责人，说明旧证据复用范围。简式见[消息与裁决模板](templates.md#消息与裁决)。

### 三会话按需参与

保留已绑定的中控、方案决策与验收、实现与验证三个入口，不为每个小任务拆分或重建角色。中控在用户指令、分派或依赖变化、阻碍及汇报节点工作；决策者在上述裁决条件触发和有可验收交付时参与；执行者推进已授权且就绪的任务。没有待处理动作的角色结束本轮，不为保持在线互发消息或持续轮询。

采用“两工作会话＋独立中控台”时，中控禁止参与生产。允许读取任务状态和已有证据，维护配置、角色回执汇总、任务台账及交接，依据用户指令和有效技术决定分派任务、报告结果。禁止自行制定项目技术方案、修改代码或项目交付文档、制作产物、运行构建或功能测试、作出验收结论，以及提交、合并、发布项目产物；不得通过另派生产子代理绕过角色边界。写调度任务时可整理目标和已有约束，不得擅自补充技术决定。状态核对不等于亲自重做验证。

任务再小、工作会话忙碌或不可用、通信失败、用户向中控提出功能需求时，中控也只按授权分派、排队或报告阻碍，不自行补位。只有用户明确变更会话方案或角色契约后，才按新职责执行；普通任务请求不视为角色变更。此限制针对独立中控，不能据此取消两会话模式中已明确兼任的方案决策与验收职责。

低风险小任务可由执行者直接完成，相关成果在约定交付节点合批验收，无须每一步调用决策者；合批不得延后依赖放行、隐瞒失败或越过用户要求的逐项验收。等待裁决或验收的部分保持待定，不能将无人回复视为通过。三个绑定会话不要求三个模型同时运行，并发仍按有效约束安排。

等待优先用宿主完成事件、`wait_threads` 与游标，单次通常不超过60秒，避免在等待调用外再套秒级轮询；无变化时不反复拉取完整历史。集中提交相关问题，不为确认收到再发确认；已授权执行不等待对方确认回执后才开工。传输失败或外部写入结果不明先查真实状态，不自动重试有重复副作用的动作。

发送报告前核对配置中的实际接收方和直接用户授权。自动审批拒绝时记录动作、接收方与原因，不变换措辞或转发路径绕过拒绝。有允许的只读会话访问时可核实实际结果，并注明取得方式；否则保留待授权回报状态。验收已完成与回报未送达分别记录，不能声称失败消息已经送达。

### 同会话的多个任务

收到直接用户新消息，先判断是当前任务的补充、兼容的独立任务，还是明确替换/取消。补充并入原任务；独立任务保留各自ID、状态和边界；明确替换/取消则停止旧任务推进并保存必要交接。无法判断且影响行动时才澄清。

切换前简记等待原因、已完成工作和下一步。本人已启动的任务应接续句柄收集结果；等待外部依赖时可推进其他已授权且就绪的任务。仅剩外部阻碍且无可推进任务时，保存返回点并结束当前轮次，等真实回复或新分派，不扩大准备工作或定时唤醒。不能兼顾时向已授权调度方说明待处理。等待不算完成，任务切换不扩展写入权限。

## 3. 实现与证据

代码与产物任务固定提交SHA或不可变源码包及SHA256，版本名称不能唯一标识基线；其他任务标明实际输入版本。默认复用独立分支、worktree或工程副本，只有明确委托才改主工程，不为每个小任务重复建副本。每批以可验收成果为单位，同一负责人、基线、写入范围和验证路径的相关小改动可合批，逐项列验收条件；用户另定粒度则遵从。

先识别现有实现、依赖与未知项，再在约定范围内完成最小改动。用真实行为和有意义的边界验证；编译通过和进程退出0不能代替案例完成。按风险核查资格、失败、取消、清理、生命周期和兼容影响，不添加只复述实现的测试。

证据绑定实际源码、构建产物与运行输入。新改动重跑受影响检查；复用旧结果说明未受影响的范围和依据。区分通过、失败、未运行与跳过。保存失败及修复关系，不能放宽断言使记录通过。

结果可疑先核对证据；确需重派时至多一次，只派未满足项，附失败证据、可信检查点和禁止重复的动作，不从头重做已有有效成果。协作收益低时由有权承担该任务的工作负责人直接完成，独立中控不得接手。

## 4. 交付、验收与整合

执行者提交 `DELIVER`：机制、源码/补丁及修改清单、实际证据身份、运行环境与日志、结果、限制、未验证项，适用时附不可变产物与校验值。只读或方案任务按其规格交付，不额外编码或生成项目文件。

验收人形成可按任务ID查到的真实 `REVIEW`，按规格判定接受、退回或部分接受，说明范围、遗留项和依据；是否发送按上述沟通规则决定，退回修复或放行后续工作须通知实际执行者。审查当前交付、关键证据及受影响行为，不重新开展全项目调查；独立复核力度按风险确定，证据缺失、失配或受影响时补验，不能只相信摘要。交付不等于验收，自查不冒充独立审查；局部演练不代表项目功能通过。共享台账由其唯一维护者引用真实验收结论更新。

退回修复应指出未满足的验收条件、可定位的证据、必须修复的范围、仍有效的成果，以及复验条件；修改偏好与阻断通过的问题分开说明，不能以退回为由增加未约定范围。执行者沿用原任务身份与历史，只修复未满足项；扩大规格或写入范围先走相应裁决或授权。再次交付引用退回项，列明修复、受影响检查和保留旧证据的依据；验收人复核修复及回归影响，不无依据重做全项目审查。技术分歧交指定裁决者，不在执行与验收之间反复争论。

整合负责人核对基线漂移与文件冲突，合并最小补丁并执行受影响检查。行为选择不明交指定裁决者。记录新基线、产物和证据，保留已验收检查点。

统计绑定当前任务目录的分母，分别报告实现、验证、验收、整合及部分完成。批次结束后，调度者在授权总目标内继续分派，执行者继续本人有效分派中已就绪的任务；没有任务则报告结果并等待，不自行抢做其他角色工作。仅全部必需成果验收和整合后才能宣布项目完成。
