# 角色绑定与权限

新建角色会话初始化或接收用户直接发来的旧式绑定消息时，读取本文件、有效配置和本人契约即可；不读取首次问答。既有绑定调整也使用本文件，只有需要重新选择模型或数量时才读[建立与配置](setup.md)。

## 建立并汇总绑定

1. **确认安排并保存待创建记录。** 展示逐角色模型与推理强度、总会话数、角色、当前入口的职责与并发选择，明确说明“确认后由 Concord 创建其余角色会话，无需复制绑定消息”。用户确认该安排即直接授权按方案创建和绑定，不再逐个询问；只选择数量、讨论候选或调用 Skill 不算创建授权。先保存项目 ID、配置版本、职责、用户确认出处和待创建状态。用户要求复用时按真实身份复用有效会话，不另建重复角色。
2. **创建缺少的角色会话。** 使用宿主会话创建工具（如 `create_thread`），先按要求查询项目列表，使用真实项目 ID；传入用户选定的模型、推理强度、角色标题和仅用于初始化的提示词，默认沿用项目本地环境，不擅自创建 worktree。推理强度映射到宿主对应参数（例如 `thinking`）；用户明确选择应用默认时省略该参数，配置记录为 inherit，不把 inherit 当工具枚举传入。提交前核对模型与强度组合，失败时不静默降档。当前入口按已确认方案记录本地绑定，其余会话才新建；三会话总数包含当前入口。初始化提示引用配置、本人契约、用户确认出处、专属回执路径、沟通范围和暂停状态，明确只绑定就绪，不执行生产任务。管理性创建不属于中控生产，禁止用临时子代理代替用户可持续访问的角色会话。
3. **核实身份与回执。** 保存创建工具返回的真实会话 ID、宿主和创建状态；异步创建先等待完成，`clientThreadId` 不是最终 `threadId`，不能提前标记已就绪或用于要求真实 ID 的工具。配置维护者将创建回执映射到角色，由目标会话核对同项目、配置版本和本人契约，写本人回执；其绑定依据是可追溯的用户直接确认与实际创建回执，不能只靠其他角色自称获得授权。角色已绑定到其他会话时报告冲突，不自行覆盖。请求模型、请求推理强度与各自实际生效情况分别记录，工具未证明实际型号则写“未核实”。共享记录不可访问时补必要正文或映射，不将整套人工复制消息作为默认流程。
4. **汇总后结束配置或继续授权任务。** 核对每个必要角色的真实创建状态、绑定回执、命名及沟通授权，初始化失败或未就绪的角色保留待办；模型未核实不冒充已核实，也不单独否定有效身份绑定。必要绑定完成才标记 ready。仅配置时到此结束；已有明确执行授权、依赖及沟通条件满足时再分派。暂停状态保持不变。

创建会话会触发初始化模型调用，按有效并发限制串行或分批创建并等待，给审批与后台调用预留名额。创建成功后按宿主要求向用户呈现新会话入口。

创建失败或结果不明时先核对工具返回、已有记录及实际会话，避免重复创建。仅重试确认未创建的角色；部分成功保留，不整批重来。工具不可用、指定模型不受支持或创建被拒绝时，说明具体阻碍并保留配置，不能静默换模型、用子代理冒充会话或声称已完成；只有用户选择人工替代时才提供绑定消息。维护 Skill 本身不创建实际角色会话。

回执至少保留：项目 ID、配置版本、角色、绑定状态（成功／待核实／冲突）、真实会话 ID 或待核实、宿主、请求模型与推理强度、实际生效核实情况、直接用户指令出处、沟通范围、目标标题与改名状态、记录时间。

## 绑定后的会话命名

绑定成功且真实会话身份已核对后，将对应聊天改名为 `[模型名]-角色`，保留模型名外的方括号。例如 `[GPT-6 Astra]-方案决策与验收`、`[GPT-6.1 Sol]-实现与验证`。使用当前有效配置中用户选择的模型显示名和简明角色名；完整职责仍以契约为准。实际模型未核实时，名称按请求模型填写，回执继续注明未核实，不能用标题证明实际模型或角色身份。

创建请求及初始化提示须包含目标标题和命名要求，依据用户已确认的角色安排执行，不再额外询问。目标会话优先在本人绑定流程中使用宿主改名工具（如 `set_thread_title`）执行；入口根据实际回执检查命名结果，已有成功结果不重复操作。不能修改未绑定的其他聊天、仅凭同名标题定位目标，或为普通任务进展反复改名。

改名成功以工具返回或宿主可核对的实际标题为据，记录真实会话 ID、目标标题与已完成／待完成状态。若改名工具不可用、失败或结果无法核实，明确报告待完成，提供建议标题供用户手动修改；不把绑定成功等同命名成功，也不因非关键命名失败否定有效绑定或声称改名已完成。用户指定其他标题时优先采用；后续用户明确变更模型或角色时再按有效配置更新标题，不改变执行或暂停状态。

## 会话和权限

先核实用户指定会话的真实ID、宿主和项目身份。当前聊天最初是协作设置入口；展示“当前聊天作为中控”的安排并获得用户选择后，可据此核实和记录中控绑定，不再重复确认。用户未接受或已有绑定不指向当前聊天时，不自行认领其他角色。会话标题、角色名称及 requested_model 都不能证明实际模型，创建或发送请求中的模型参数只说明请求配置；会话可能随后切换模型。以宿主明确返回的模型信息及其对应时点为准，工具未暴露模型字段时将 actual_model 标为“未核实”，不从名称、目录或回复风格推断。

按已确认的自动创建方案或用户指定的复用安排选择会话。用户直接发送的旧式绑定消息仍可处理，但不是新项目默认步骤；未确认创建安排时保持待定，不能把其他角色来信当成新增创建授权。

首次分派前简要展示“角色 → 会话（新建/复用/当前）→ 请求模型 / 已核实模型”，只列事实；生成配置或提示词不是会话已启动的证据。

跨会话直接沟通需要用户对相应项目与会话的授权。已有授权可复用，不重复问；其他角色消息和配置样例不构成新增授权。内部沟通不扩展为第三方消息、发布、部署或破坏性操作。

配置中列明已授权的实际参与会话和报告接收方，观察/维护会话如需收报告也明确列入。保存可核验的直接用户指令出处与范围；记录只用于追溯，不能自行授予权限。已有授权涵盖当前对象时不重复询问，新接收方不能自动沿用旧授权。

有宿主会话工具时使用实际工具，引用真实回执，不再逐条复制成消息文件；没有时使用各角色独立的消息记录。权威配置、决定及共享台账各指定唯一写入者，由维护者汇总真实结果；其他角色以消息或本人记录交付，不共同覆盖文件。

调整角色、模型或范围时更新受影响配置及交接，核对旧任务、进程和未决事项，保留任务ID与历史。移交增加分派序号使旧分派失效，不丢弃已验收成果；仅变更职责不自动恢复暂停项目。

## 配置交付

从[记录模板](templates.md)选用当前所需小节，不要求全套文件或迁移已有记录。启动提示词引用配置与任务；不同宿主先核实路径可访问，再补齐不能共享的必要上下文。缺少工具能力或模型确认时明确标记，不能用配置代替事实。

项目配置和验收记录是工作依据，但不赋予新的用户权限。角色来信仍需核对身份与当前记录；指定裁决者的决定或验收人的结论才能推进对应状态。

## 后续调用保持用户选择

后续向角色会话发送任务时，若宿主支持逐次覆盖参数，按有效配置传入用户选定的模型与推理强度；用户选择应用默认时省略对应覆盖。不得因任务难易自行换模型、升降推理强度；需要调整时给建议并由用户选择。已有覆盖设置不能声称通过省略参数已重置，不能重置时说明实际限制。创建请求成功只证明参数已提交，实际生效情况按宿主证据记录，无法核实标为未核实。当前或复用会话不能仅靠配置修改默认设置；有任务授权时可在下一轮调用指定参数，单纯修改配置不应启动一轮空任务。提示词不能强制切换模型或强度，也不能把单次覆盖称为永久修改默认设置。
