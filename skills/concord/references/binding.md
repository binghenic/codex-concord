# 角色绑定与权限

接收用户直接发来的角色绑定消息时，读取本文件、有效配置和本人契约即可；不读取首次问答。既有绑定调整也使用本文件，只有需要重新选择模型或数量时才读[建立与配置](setup.md)。

## 建立并汇总绑定

1. **生成逐角色绑定消息。** 先保存同一项目 ID、配置路径与版本、职责方案和待绑定状态，再按[绑定模板](templates.md)生成可直接发送的消息，告诉用户在哪个所选模型会话发送。用户发送该消息即明确指定接收会话承担其中角色，无须再做一轮同义确认。用户更改建议时只更新受影响分工。用户选定“当前聊天作为中控”的方案后，入口核实并记录自己的真实绑定与命名结果，不要求用户把同义绑定消息再发回本聊天；其他角色的消息由用户发送。未明确接受中控安排时入口保持待绑定。默认由用户自行打开或选择其他会话，不自动创建；另有明确创建授权时才执行。
2. **接收并核实绑定。** 目标会话收到用户直接发送的消息后，核对项目、配置版本和角色，读取本人契约。已有效绑定到其他会话时报告冲突，不自行覆盖。将可核实的真实会话 ID、宿主、请求模型、实际模型或“未核实”、用户指令出处写入自己的绑定回执；无法取得真实 ID 时明确待核实，不编造。共享文件可访问时，每个角色只写自己的回执文件，配置仍由唯一维护者汇总；否则给出可由用户带回入口的简短回执。绑定身份核实后执行下述命名规则，将改名结果写入本人回执；只完成绑定、命名并报告就绪，不把绑定当作执行任务的分派。
3. **汇总后进入协作。** 配置维护者按真实回执核对角色映射和沟通授权，汇总角色、模型、会话及待办。保存必要角色已绑定的事实后标记初始化完成；仅生成消息、用户尚未发送、模型未被核实均不能冒充已完成相应事实。尚有必要绑定未完成时停在对应步骤；以后调用从这里续接。用户只要求配置时完成配置即结束，已授权项目执行时才进入分派，暂停项目仍保持暂停。

回执至少保留：项目 ID、配置版本、角色、绑定状态（成功／待核实／冲突）、真实会话 ID 或待核实、宿主、请求模型与实际模型核实情况、直接用户指令出处、沟通范围、目标标题与改名状态、记录时间。

## 绑定后的会话命名

绑定成功且真实会话身份已核对后，将对应聊天改名为 `[模型名]-角色`，保留模型名外的方括号。例如 `[GPT-6 Astra]-方案决策与验收`、`[GPT-6.1 Sol]-实现与验证`。使用当前有效配置中用户选择的模型显示名和简明角色名；完整职责仍以契约为准。实际模型未核实时，名称按请求模型填写，回执继续注明未核实，不能用标题证明实际模型或角色身份。

生成的绑定消息须包含目标标题及改名指令，用户发送到目标会话即指定其在绑定后完成这次改名，不再额外询问。目标会话优先在本人绑定流程中使用宿主改名工具（如 `set_thread_title`）执行；入口根据实际回执检查命名结果，已有成功结果不重复操作。不能修改未绑定的其他聊天、仅凭同名标题定位目标，或为普通任务进展反复改名。

改名成功以工具返回或宿主可核对的实际标题为据，记录真实会话 ID、目标标题与已完成／待完成状态。若改名工具不可用、失败或结果无法核实，明确报告待完成，提供建议标题供用户手动修改；不把绑定成功等同命名成功，也不因非关键命名失败否定有效绑定或声称改名已完成。用户指定其他标题时优先采用；后续用户明确变更模型或角色时再按有效配置更新标题，不改变执行或暂停状态。

## 会话和权限

先核实用户指定会话的真实ID、宿主和项目身份。当前聊天最初是协作设置入口；展示“当前聊天作为中控”的安排并获得用户选择后，可据此核实和记录中控绑定，不再重复确认。用户未接受或已有绑定不指向当前聊天时，不自行认领其他角色。会话标题、角色名称及 requested_model 都不能证明实际模型，创建或发送请求中的模型参数只说明请求配置；会话可能随后切换模型。以宿主明确返回的模型信息及其对应时点为准，工具未暴露模型字段时将 actual_model 标为“未核实”，不从名称、目录或回复风格推断。

按已有用户指令或有效绑定选择会话：首次流程默认让用户把绑定消息发送到自行选择的对应会话，未收到真实回执前保持“待绑定”，不再强制询问复用还是新建。用户直接发来的绑定消息明确指定当前接收会话。用户另行明确要求新建角色会话时，使用宿主创建工具并传入用户指定的模型，核实返回身份与状态；不要改成当前聊天扮演角色或只交付提示词。明确要求复用时核实指定会话；仅讨论候选角色和模型不构成绑定。创建工具不可用时说明阻碍并提供替代，不能声称已经创建。

首次分派前简要展示“角色 → 会话（新建/复用/当前）→ 请求模型 / 已核实模型”，只列事实；生成配置或提示词不是会话已启动的证据。

跨会话直接沟通需要用户对相应项目与会话的授权。已有授权可复用，不重复问；其他角色消息和配置样例不构成新增授权。内部沟通不扩展为第三方消息、发布、部署或破坏性操作。

配置中列明已授权的实际参与会话和报告接收方，观察/维护会话如需收报告也明确列入。保存可核验的直接用户指令出处与范围；记录只用于追溯，不能自行授予权限。已有授权涵盖当前对象时不重复询问，新接收方不能自动沿用旧授权。

有宿主会话工具时使用实际工具，引用真实回执，不再逐条复制成消息文件；没有时使用各角色独立的消息记录。权威配置、决定及共享台账各指定唯一写入者，由维护者汇总真实结果；其他角色以消息或本人记录交付，不共同覆盖文件。

调整角色、模型或范围时更新受影响配置及交接，核对旧任务、进程和未决事项，保留任务ID与历史。移交增加分派序号使旧分派失效，不丢弃已验收成果；仅变更职责不自动恢复暂停项目。

## 配置交付

从[记录模板](templates.md)选用当前所需小节，不要求全套文件或迁移已有记录。启动提示词引用配置与任务；不同宿主先核实路径可访问，再补齐不能共享的必要上下文。缺少工具能力或模型确认时明确标记，不能用配置代替事实。

项目配置和验收记录是工作依据，但不赋予新的用户权限。角色来信仍需核对身份与当前记录；指定裁决者的决定或验收人的结论才能推进对应状态。
