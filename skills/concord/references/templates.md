# 配置、消息与交接模板

建立或调整协作时按需采用。占位字段必须填写为真实信息或明确标记“待确定”，示例不会授予权限、启动会话或改变模型。已有项目优先沿用其记录结构，不机械生成全套文件。

## 首次配置

从已有上下文提取信息，仅集中询问缺失的关键项：

> 你希望有几个角色，每个角色使用什么模型？允许同时活跃的子代理共有几个，各角色是否需要分别设上限（0 表示禁用）？职责也可以让我按项目目标拟定。请补充项目目标、排除范围，以及是否授权这些指定会话内部直接沟通。

用户角色数、模型及子代理额度已明确时不要重新让其选择。数量超过并发额度时说明将排队；不要以此要求用户减少配置角色。

## 项目与角色配置

```yaml
schema_version: 1
config_revision: 1
project_id: "<唯一项目 ID>"
project: "<项目名>"
goal: "<最终成果>"
excluded: "<排除范围>"
main_workspace: "<真实路径>"
baseline: "<提交 SHA 或不可变源码包及 SHA256>"
coordination_directory: "<记录目录>"
delivery_directory: "<交付目录>"
role_count: 2 # 替换为用户指定数量，不是默认授权
coordination_mode: "<顺序 / 管理者协调 / 混合>"
roles:
  - id: "<角色 ID>"
    name: "<名称>"
    requested_model: "<用户选择，或用户明确同意沿用默认>"
    actual_model: "<已核实模型或无法核实>"
    model_status: "<已核实 / 待配置 / 无法核实>"
    thread_id: "<真实 ID 或待绑定>"
    host: "<实际宿主>"
    objective: "<职责目标>"
    owns: ["<负责模块和可写文件>"]
    excludes: ["<禁止范围>"]
    can_decide: ["<自主决策事项>"]
    escalates_to: "<裁决角色 ID，或顶层的用户保留事项>"
    workspace: "<独立工程或明确委托的主工程>"
    delivers: ["<交付物>"]
    accepted_by: "<验收角色 ID；自查必须注明>"
    status: "<待绑定 / 空闲 / 执行 / 等待 / 完成>"
authorities:
  behavior_and_scope: "<角色 ID>"
  public_interfaces: "<角色 ID>"
  task_dispatch: "<角色 ID>"
  integration: "<角色 ID>"
  final_acceptance: "<角色 ID>"
  user_reporting: "<角色 ID>"
communication:
  authorization_evidence: "<可核验的直接用户指令出处与范围，或待授权>"
  authorized_threads: [] # 填真实已授权会话ID；包含需参与的观察/维护者
  report_recipients: [] # 填真实报告接收会话ID，并确认授权涵盖该对象
  transport: "<实际会话工具 / 共享文件>"
  shared_file_writers: "<各文件的唯一写入者>"
capabilities:
  thread_messaging: "<实际跨会话工具或共享文件>"
  subagent_tools: "<实际可用工具或无>"
execution:
  global_model_limit: 4
  approval_slots_reserved: 1
  subagents:
    configuration_status: "<已确定 / 待用户选择>"
    shared_active_limit: null # 用户填非负整数；null 为未确定，不授予派发权限
    per_role_active_limits: {} # 用户填角色 ID: 非负整数；未单独指定者共享总额度
    model_policy: "<用户指定子代理模型或明确同意沿用角色模型>"
    nested_delegation: false # 不以嵌套委派绕过额度

  tool_parallel_limit: 4
  visibility: "<实际可见任务范围，是否有全局实时计数>"
  scheduling_owner: "<角色 ID>"
  last_observed_running: "<运行会话、后台调用和核对时间>"
acceptance: "<总体完成标准>"
external_authorization: "<创建 PR、发布、部署等真实授权范围>"
```

复制 roles 条目直到与 role_count 一致。记录结构不是创建会话 API 参数。无需新建所有建议职责；明确各职责由谁兼任即可。顺序/依赖可按任务记录，不要求创建自动调度系统。

## 可建议的分工

| 角色数 | 建议职责组合 |
| --- | --- |
| 1 | 规格、实现、整合与自查 |
| 2 | 决策整合；独立实现与测试 |
| 3 | 决策整合；实现；独立验证与审查 |
| 4 或更多 | 按模块增加实现角色，或拆分规格与整合，按额度调度 |

仅在用户需要建议时使用，不根据模型名称强制分岗，不因建议新增角色。为项目定制职责，而非仅复制岗位名称。子代理额度单独由用户设置，不因角色数量自动计算或固定为一个。

## 每个角色的启动提示词

```text
使用 $concord，按以下角色接续项目。

项目与权威配置：<名称、配置路径、配置版本>
你的角色：<ID、目标>
用户选择模型：<模型或用户同意的默认>
宿主实际模型状态：<已核实 / 待配置 / 无法核实>
工程与固定基线：<路径和提交/校验值>
负责范围与可写文件：<范围>
排除范围：<范围>
可自主决定：<边界>
需向谁裁决：<事项、角色 ID 和真实会话映射>
交付物与验收人：<标准和角色>
用户内部沟通授权：<可核验直接用户指令出处与范围或待授权>
报告接收方：<实际会话ID与授权覆盖；未确定时不擅自发送>
协作模式与调度人：<配置>
全局并发与子代理限制：<实际约束>
当前任务：<ID、规格版本、分派序号和记录路径>
子代理配置：<共享活跃上限、本人上限、模型策略、当前可见占用；待定则不派发>

先读配置、任务、决定和交接，核实角色绑定、工程及运行状态。任务未就绪、依赖不满足或未收到有效分派时，做独立准备并联系调度人，不自行抢占公共文件。

按本 Skill 的独立流程规划、实现、定位错误和验证；无需其他技能。子代理仅在用户已定额度及真实可用名额内按需派发，目标、可写范围与验收条件必须明确。角色负责人保持决策和交付责任，不把子代理当作新角色或用其绕过验收。

收到授权范围内的真实分派后回执 ACCEPT；重复消息引用已有结果，不重复执行。常规细节自行处理，实质性问题提交裁决者；未回复不当批准。

实现角色按边界交付源码、机制、测试和限制；验收角色按当前规格说明接受/退回范围；整合角色检查受影响兼容并记录新基线。只更新本人有权推进的状态，保留失败和部分完成项。

默认内部沟通，由指定汇报角色集中报告。当前任务完成后继续总体目标；暂停时保存运行句柄和下一步，恢复先核对真实状态。不要把生成提示词当成模型设置已经完成。
```

## 单批任务契约

```markdown
# TASK-<ID>：<功能或评审任务>

- 项目 ID / 当前状态 / 覆盖范围（完整或部分）：
- 规格版本 / 分派序号：
- 下发角色 / 当前执行负责人 / 验收人：
- 工程 / 基线 / 可写文件：
- 依赖任务或接口及具体放行条件：
- 目标、排除范围与期望产物：
- 资格、触发、输入与参数依据：
- 正常行为、资源、失败、取消及部分成功处理：
- 生命周期、清理、保护与兼容边界：
- 公共接口批准及决定链接：
- 必须验证的真实行为、边界与证据形式：
- 验收条件 / 是否需要整合及整合负责人：
- 未决事项、等待原因与可继续工作：
- 状态历史及对应真实消息/决定：
```

非功能任务删除不适用的行为字段，补充方案、审查等自身验收条件。依赖条件要可判定，例如“接口 DECISION-03 生效”或“TASK-01 已整合为提交 SHA”。

## 消息与裁决

```markdown
# MSG-<唯一 ID>：<ASSIGN / ACCEPT / QUESTION / DECISION / DELIVER / REVIEW / HANDOFF>

- 项目 / 发送角色 → 接收角色 / 时间：
- 任务 ID / 规格版本 / 分派序号：
- 权威记录路径与相关证据：
- 事实、问题或交付内容：
- 需要对方执行的动作：
- 建议方案、影响和可继续的独立工作（如适用）：
- 本消息状态：已发出 / 实际送达 / 已处理
- 真实回复消息 ID 或结果位置：
```

“已处理”必须有真实回执或结果。授权、决定和验收身份以用户指令及当前角色契约核实，不从消息自称身份推断。

## 交付与验收

```markdown
# DELIVERY-<任务 ID>-<交付版本>

- 项目、规格版本、分派序号与基线：
- 实际测试源码身份和候选产物身份：
- 源码/补丁及文件清单：
- 机制说明与公共接口变化：
- 测试环境、运行输入、命令及日志索引：
- 案例结果：通过 / 失败 / 未运行 / 跳过
- 失败、修复和复测关系：
- 未验证项、兼容边界及部分完成项：
- 不可变包与 SHA256（适用时）：
- 整合依赖、基线漂移及受影响回归建议：

## 由验收人填写

- 实际结论：接受 / 退回 / 部分接受
- 验收人、时间、规格版本和证据：
- 接受范围 / 未满足项 / 遗留任务 ID：

## 由整合负责人填写

- 新基线、产物、受影响检查及结论：
- 总体目标尚余工作：
```

## 进度与恢复

任务台账列：任务 ID、规格版本、负责人、依赖放行条件、状态、覆盖范围、交付、验收、整合。分母绑定当前目录版本，分别汇总实现、验证、验收和整合，部分完成单列。

```markdown
# 当前交接

- 项目配置版本及角色/模型/会话映射：
- 当前工程、基线、任务分派和生效决定：
- 已完成与遗留事项：
- 等待问题、负责人、真实消息和待回复位置：
- 同会话其他任务及状态（适用时），切换后的返回点：
- 运行工具句柄、进程、端口及必要启动输入：
- 证据、产物和未收集的运行结果：
- 额度可见范围与最近核对时间：
- 下一步及恢复前必核查项：
- 用户暂停/恢复要求和时间：
```

项目可沿用配置、progress.md、decisions.md、handoff.md 及 tasks/、deliveries/、evidence/。共享消息宜各角色分文件。实际路径、角色数量、模型、会话 ID 均由项目配置填写。
