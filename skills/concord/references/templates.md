# 记录模板

只读当前需要的小节：首次配置、项目与角色、启动、任务、消息、交付、交接。沿用已有结构，不机械建立全套文件；无关字段可省略。占位符须填写真实信息或标为待确定，不能据此启动会话、改变模型或获得授权。

## 首次配置

提问与推荐以[首次配置流程](setup.md)为准；这里只提供持久记录格式，不重述问答。

## 项目与角色配置

适用于需要持久协作的项目；一次明确分派可直接使用任务记录。下面字段按需保留，既有项目无需迁移格式。

```yaml
schema_version: 1
config_revision: 1
project_id: "<唯一 ID>"
goal: "<成果与排除范围>"
main_workspace: "<真实路径>"
baseline: "<提交 SHA / 源码包 SHA256 / 非代码输入版本>"
coordination_directory: "<权威记录目录>"
initialization:
  status: "<configuring / ready>" # 可选；旧配置按实际记录判断，不强制补字段
  pending: ["<未完成的模型选择、角色绑定或必要授权；没有则空列表>"]
concurrency: # 可选；旧项目沿用已有有效规则
  mode: "<inherit / limited>" # inherit 不新增项目上限，不取消原有限制
  max_active_model_calls: null # limited 时填写用户选择的正整数
  scope: "<本项目合计；或用户指定共享渠道及参与会话>"
roles:
  - id: "<角色 ID>"
    requested_model: "<用户选择或已认可的默认>"
    requested_reasoning_effort: "<用户选择的宿主支持档位 / inherit；未选择则待定>"
    actual_reasoning_effort: "<已核实档位或未核实>"
    actual_model: "<工具已核实的模型或无法核实>"
    thread_id: "<真实 ID 或待绑定>"
    display_title: "<[用户选择的模型显示名]-简明角色名>"
    title_status: "<待改名 / 已核实完成 / 用户自定>"
    host: "<宿主>"
    workspace: "<真实路径>"
    objective: "<职责>"
    owns: ["<模块与可写文件>"]
    excludes: ["<排除项>"]
    can_decide: ["<自主事项>"]
    escalates_to: "<裁决角色或用户保留事项>"
    delivers: ["<交付物>"]
    accepted_by: "<验收角色；自查注明>"
authorities:
  behavior_and_scope: "<角色 ID>"
  public_interfaces: "<角色 ID>"
  task_dispatch: "<角色 ID>"
  integration: "<角色 ID 或不适用>"
  final_acceptance: "<角色 ID>"
  user_reporting: "<角色 ID>"
communication:
  authorization_evidence: "<直接用户指令出处与范围或待授权>"
  authorized_threads: [] # 真实已授权会话 ID
  report_recipients: [] # 包含需收报告且已获授权的观察/维护会话
  transport: "<实际会话工具 / 各角色独立文件>"
  shared_file_writers: "<配置、决定、台账等各文件的唯一维护者>"
acceptance: "<总体完成标准>"
external_authorization: "<PR、发布、部署等真实授权范围>"
```

三会话中独立中控的 owns 仅包含协作管理记录，excludes 明确列出项目技术方案、生产文件、构建测试、验收及提交整合发布；不得把中控列为生产任务的执行人或验收人。两工作角色的权限分别写入各自契约。

每个用户选定角色添加一条 roles。职责可兼任，配置字段不是宿主工具参数；身份核实与绑定按[角色绑定与权限](binding.md)执行。

## 创建会话的初始化提示与回执

默认由入口填写以下提示并交给会话创建工具，用户无需复制发送。先核对直接用户确认出处；沟通授权须另有真实依据，不能从模板推定。用户明确选择人工替代时，才将其改为可转发的绑定消息。

```text
使用 $concord，初始化当前新建会话并绑定为项目 <项目 ID> 的 <角色 ID / 名称>。
配置：<可访问的绝对路径>#<配置版本>；请求模型：<用户选定的具体型号>；推理强度：<用户选择的支持档位或明确沿用应用默认>。
职责：<范围、交付物、验收关系及兼任情况>。
绑定身份核实后，请使用宿主改名工具将当前聊天命名为 <已填好的目标标题，例如 [GPT-6 Astra]-方案决策与验收>；工具不可用或失败时注明待改名，不声称完成。
并发：<沿用现有约束，或用户已选定的上限及统计范围；未确定不得猜测>。
创建授权：<用户直接确认出处及范围>；创建身份以宿主真实回执为准。请核对配置和已有绑定，记录可核实的会话 ID、宿主和实际模型，无法核实的内容明确注明。
请把绑定回执写入 <当前角色专属的绝对回执路径>，不要直接覆盖共享配置；路径不可访问时在本会话给出回执，报告配置入口待补齐的内容。
<按用户选择填写沟通范围：授权当前会话与本项目已绑定且获授权的参与会话传递项目任务、问题与结果，或暂不授权直接消息、由用户转交。>
本次只绑定、完成聊天命名并报告结果，等待有效任务分派；沿用项目的暂停状态，不自行启动工作。
```

回执按[绑定流程](binding.md)记录身份、模型核实情况、授权出处及命名结果。各角色只写自己的回执，配置维护者汇总；缺失的沟通授权不能从模板推定。

## 角色启动提示词

适用于接收方可访问权威记录的情况；跨宿主先核实路径映射，不能访问时补相关原文，不复制无关项目历史。

```text
使用 $concord 接续项目 <项目 ID>。
配置：<绝对路径及版本>；角色：<ID>；当前任务：<路径、ID、规格版本/分派序号>。
先确认当前会话确为该角色的有效绑定；未绑定或不匹配时先报告，不自行认领。按配置核对用户模型选择、实际能力、授权和暂停状态，再读取本人契约、当前任务与相关生效决定。边界、验收人和返回位置以这些记录为准。
只执行本人已获有效分派且依赖满足的任务，常规实现自主完成；已启动的任务先收集结果。仅剩外部阻碍时报告并结束本轮，等真实回复或新分派。
交付说明结果、证据位置、失败及未验证项；不得代填他人的验收结论。领域实现与验证按需使用相关技能。
```

## 单批任务契约

```markdown
# TASK-<ID>：<成果>

- 项目 / 当前状态 / 规格版本 / 分派序号：
- 下发者 / 执行负责人 / 验收人：
- 工程或输入 / 固定基线 / 可写范围：
- 目标、排除项与交付物：
- 相关接口或决定 / 依赖放行条件：
- 必须验证的行为与边界 / 验收条件：
- 是否需要整合 / 整合负责人：
- 未决项、等待原因与下一步：
- 交付、验收及整合的真实记录位置：
```

稳定字段可引用配置。相关小改动可合批，验收项分别列出；生命周期、取消、清理等只在与任务相关时补充。依赖写成可判断的条件，例如某决定生效或某任务已整合为指定 SHA。

## 消息与裁决

```text
<类型> | <项目> | <发送角色 → 接收角色>
任务：<ID / 规格版本 / 分派序号>；记录：<可访问路径与版本>。
结论或变化：<必要内容>；需要动作或交付目的：<接收方要做什么，或用户要求交付什么>。
消息 ID：<真实传输回执，或发送方生成的唯一 ID>。
```

类型为 ASSIGN、ACCEPT、QUESTION、DECISION、DELIVER、REVIEW、HANDOFF；合发时列明各类型及对应事实。问题或裁决补最小方案与影响。身份、授权和当前分派以真实用户指令及权威记录核实，不从消息自称身份推断。

需要裁决时，在上述消息身份后按需使用：

```text
QUESTION
问题与证据：<歧义、已调查事实与关键证据位置>
建议与影响：<建议方案、影响；未知明确标注>
需要决定：<具体选择或边界>；等待期间可继续：<已授权独立工作或无>。

DECISION
决定与约束：<方向、理由及限制>；放行条件：<哪些工作可继续>。
生效记录：<规格/决定路径与版本>；影响：<负责人及旧证据复用范围>。
```

使用会话工具时不为每条消息另建文件；只有送达回执不能标为已处理，须有对方的实际接收或结果。简短结果可直接作为记录，需要持久证据时引用正文，避免两处重复全文。消息合并不改变验收责任。

## 交付与验收

由执行者写交付记录；验收人与整合人在各自可查结果或有权维护的记录中给出结论，需要对方行动或指定汇报时再发送，由台账唯一维护者引用。不要为通知无后续动作的验收结果唤醒已结束的执行者。

```markdown
# DELIVERY-<任务 ID>-<交付版本>

- 项目 / 规格版本 / 分派序号 / 基线：
- 源码、补丁与修改清单 / 实际测试对象及候选产物身份：
- 机制及接口变化：
- 实际测试环境、输入、命令 / 日志或证据位置：
- 案例结果：通过、失败、未运行、跳过分别标明
- 失败修复与复测 / 未验证项、部分完成及遗留事项：
- 整合依赖、基线漂移与受影响检查建议：
```

不可变包及 SHA256 在需要交付产物时补充。REVIEW 给出验收人、任务/规格/分派身份、接受/退回/部分接受、范围及证据；整合结论给出新基线、受影响检查及遗留项。执行者不能替验收人下结论。

退回时在 REVIEW 的任务身份、结论和范围后列出必要信息，不另建重复台账：

```text
未满足项：<验收条件及可定位证据>
必须修复：<范围与预期行为>；仍有效：<可保留成果、证据及适用范围>。
复验条件：<修复后需要核对的行为与受影响检查>。
```

修复交付沿用原任务及当前有效规格/分派，引用退回记录，补充“退回项 → 修复与证据”、受影响检查和未完成项。无关成果不重做；非阻断建议单独注明。

## 进度与交接

沿用项目台账，按当前任务目录分别记录实现、验证、验收、整合及部分完成，不新增重复状态文件。

```markdown
# 当前交接

- 更新时间 / 当前工程版本 / 最后已验收基线 / 暂停或运行状态：
- 配置 / 角色与会话映射 / 当前有效任务、规格、分派及决定：<路径与版本>
- 工程与基线 / 已完成及遗留：<引用记录，只补变化>
- 等待问题、负责人、真实消息与待回复位置：
- 运行句柄、进程、端口 / 未收集结果 / 必要启动输入：
- 同会话其他任务及返回点（如有）：
- 下一步 / 恢复前必查项 / 用户暂停或恢复要求及时间：
```
