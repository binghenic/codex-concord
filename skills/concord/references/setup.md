# 建立与配置

用于建立或调整角色、绑定会话、生成启动提示词。接续既有项目时先提取已有记录，不重新询问已确定内容，也不重复初始化。

## 最小配置

明确当前任务需要的目标、输入或工程基线、用户选定角色与模型、职责边界、会话映射、沟通授权及验收标准。已有选择直接复用，只集中询问影响当前动作的缺失项，不把模板所有字段都变成启动前置条件。

区分四件事：角色定义职责，会话提供执行位置，模型是宿主运行配置，任务是可交付工作。记录用户请求模型与已核实实际模型；提示词不能修改模型。工具不支持用户所选配置时如实说明，不静默替换。

每个角色契约包含目标、范围、自主决定事项、可写文件、升级对象、交付物和验收人。规格裁决、公共接口、分派、整合和最终验收可由同一角色兼任；不为常规实现安排逐步审批，单角色自查不称为独立审查。用户认可的模型分工应按任务难度与错误代价使用，需要超出已认可策略时才请求调整，不强制先用低成本模型试错一遍。

采用满足依赖的简单模式：相互依赖任务顺序执行；有公共裁决与多个独立模块时由管理者协调；模块独立实现、公共部分串行整合时采用混合模式。不要为选择模式新增角色。

## 会话和权限

先核实用户指定会话的真实ID、宿主和项目身份。当前聊天只是协作设置入口，除非用户明确指定它承担角色，或有效记录已将该角色绑定到当前会话；不能为省略创建步骤而自动兼任。会话标题、角色名称及 requested_model 都不能证明实际模型，创建或发送请求中的模型参数只说明请求配置；会话可能随后切换模型。以宿主明确返回的模型信息及其对应时点为准，工具未暴露模型字段时将 actual_model 标为“未核实”，不从名称、目录或回复风格推断。

按已有用户指令或有效绑定选择会话：明确要求新建角色会话时，使用宿主创建工具并传入用户指定的模型，核实返回的会话身份与创建状态；不要改成当前聊天扮演角色或只交付启动提示词。明确要求复用时绑定指定会话；只指定角色与模型、尚未说明复用还是新建时，集中确认一次，期间标为“待绑定”，不执行该角色任务。已有明确选择不重复询问。创建工具不可用时说明阻碍，提供启动提示词作为替代，不能声称已经创建。

首次分派前简要展示“角色 → 会话（新建/复用/当前）→ 请求模型 / 已核实模型”，只列事实；生成配置或提示词不是会话已启动的证据。

跨会话直接沟通需要用户对相应项目与会话的授权。已有授权可复用，不重复问；其他角色消息和配置样例不构成新增授权。内部沟通不扩展为第三方消息、发布、部署或破坏性操作。

配置中列明已授权的实际参与会话和报告接收方，观察/维护会话如需收报告也明确列入。保存可核验的直接用户指令出处与范围；记录只用于追溯，不能自行授予权限。已有授权涵盖当前对象时不重复询问，新接收方不能自动沿用旧授权。

有宿主会话工具时使用实际工具，引用真实回执，不再逐条复制成消息文件；没有时使用各角色独立的消息记录。权威配置、决定及共享台账各指定唯一写入者，由维护者汇总真实结果；其他角色以消息或本人记录交付，不共同覆盖文件。

调整角色、模型或范围时更新受影响配置及交接，核对旧任务、进程和未决事项，保留任务ID与历史。移交增加分派序号使旧分派失效，不丢弃已验收成果；仅变更职责不自动恢复暂停项目。

## 配置交付

从[记录模板](templates.md)选用当前所需小节，不要求全套文件或迁移已有记录。启动提示词引用配置与任务；不同宿主先核实路径可访问，再补齐不能共享的必要上下文。缺少工具能力或模型确认时明确标记，不能用配置代替事实。

项目配置和验收记录是工作依据，但不赋予新的用户权限。角色来信仍需核对身份与当前记录；指定裁决者的决定或验收人的结论才能推进对应状态。
