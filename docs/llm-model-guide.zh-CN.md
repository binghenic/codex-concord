# 主流 LLM 模型与任务选择指南

资料核对日期：2026-10-15（北京时间）。

本文供项目负责人和 Concord 首次配置时参考，覆盖 OpenAI、Anthropic、DeepSeek、智谱 AI、月之暗面五家服务商。先说明模型的类别，再按服务商列出代表模型与适用任务，最后给出项目分工建议。

本文的“适合任务”是根据官方定位整理的选型建议，不是五家模型的统一实测排名。模型版本、路由、价格与账号权限会变化；真正配置项目时，还要核对用户实际能用的型号。

## 1. 先分清服务商、模型、产品和角色

| 名称 | 含义 | 示例 |
| --- | --- | --- |
| 服务商 | 提供模型或 API 的机构 | OpenAI、Anthropic、DeepSeek、智谱 AI、月之暗面 |
| 模型家族 | 同一品牌下的一组模型 | GPT、Claude、DeepSeek、GLM、Kimi |
| 具体模型 | 实际选择的版本或规格 | Claude Sonnet 5.5、GLM-5.3 |
| API 模型 ID | 请求里传入的模型标识，可能是动态别名 | `claude-sonnet-5-5`、`deepseek-flash` |
| 产品或运行环境 | 承载模型、工具和会话的应用 | ChatGPT、Codex、Claude Code、Kimi 网页端 |
| 项目角色 | 用户为协作指定的责任 | 方案负责人、执行者、独立验收人 |

智谱 AI 起源于清华大学技术成果转化，本文使用服务商名称“智谱 AI”；“清华”不是它的模型名称。

模型能力与运行环境提供的能力要分别核对。模型能够理解图像，不代表当前会话能接收图片；模型能够调用工具，也不代表当前应用已提供浏览器、文件权限或终端。网页产品里能用的型号，也不保证同一账号能通过 API 调用。

## 2. LLM 的常见类型

这些类型可以重叠。一个模型可以同时支持通用对话、推理、视觉和工具调用，并不需要为每种能力单独配置一个角色。

| 类型 | 主要特点 | 适合做的内容 | 选用时重点看什么 |
| --- | --- | --- | --- |
| 通用模型 | 理解指令，处理多类文本工作 | 日常问答、翻译、内容整理、文案、常规分析 | 指令遵循、中文质量、输出稳定性 |
| 推理模型／思考模式 | 对复杂问题投入更多推理过程 | 数学、算法、方案取舍、复杂排错、约束分析 | 正确率、耗时、是否能验证结论 |
| 编程与 Agent 模型 | 面向代码、工具调用和多步骤执行优化 | 功能开发、修复缺陷、重构、测试、仓库调查 | 工具成功率、改动范围、能否完成验证 |
| 快速／轻量模型 | 面向低延迟或高调用量工作 | 分类、提取、摘要、格式转换、范围清晰的小修改 | 每项合格结果的成本、延迟、失败率 |
| 长上下文模型 | 一次接收较多资料 | 长文档问答、合同对照、代码库材料整理、跨文件分析 | 关键信息召回、引用准确性、输入成本 |
| 多模态模型 | 接收文本以外的输入，具体模态因版本而异 | 看图表、理解截图、分析扫描文档、解释界面 | 当前版本支持的输入、清晰度限制、实际工具链 |
| 开放权重模型 | 可在许可和资源允许时自行部署 | 本地知识库、内网应用、专门微调、部署控制 | 许可证、硬件、运维、量化后的效果 |

“推理强”不等于所有任务都值得开最高思考强度；“上下文长”不等于能准确记住全部输入。检索、分段和清晰的任务范围仍然重要。

开放权重是部署与许可属性，不是能力等级。嵌入、重排、图像生成、语音生成模型也常由这些服务商提供，但它们不是本指南的通用 LLM 分工对象。

不要仅凭“Flash”推断这是弱小模型，也不要把两个不同请求 ID 自动当成两种独立模型。复杂推理和工程任务是否适合，仍要用项目样例检查正确性、工具成功率和总耗时。

## 8. 按要完成的工作选择候选

下表是筛选起点，各行没有排名，候选也不是排他清单。OpenAI 选项沿用第 3 节的“官网待复核”标记；实际选择以用户可用模型及样例结果为准。

| 工作 | 优先检查的能力 | 可以比较的候选示例 | 应交付的结果 |
| --- | --- | --- | --- |
| 需求澄清与方案设计 | 找出歧义、处理约束、解释取舍 | GPT-6 Astra；Claude Fable／Opus；GLM-5.3；Kimi K3；DeepSeek-V4.1-Flash | 目标、范围、取舍依据、验收条件 |
| 日常功能开发 | 读懂代码、控制改动范围、使用工具 | GPT-6.1 Sol；Claude Sonnet／Opus；GLM-5.3；Kimi K2.7 Code／K3；DeepSeek-V4.1-Flash | 可审阅的改动与实际验证结果 |
| 困难缺陷与架构问题 | 根因分析、跨文件理解、比较假设 | GPT-6 Astra；Claude Fable／Opus；GLM-5.3；Kimi K3；DeepSeek-V4.1-Flash | 复现、证据、修复及回归验证 |
| 中文文档与写作 | 准确表达、遵守结构、保持术语一致 | Claude Sonnet／Opus；GLM-5.3-Flash；Kimi K3；DeepSeek-V4.1-Flash；用户接入中可用的 GPT 主力 | 符合读者和用途的文稿，事实有出处 |
| 长材料阅读与研究整理 | 召回、引用、跨材料一致性 | Kimi K3；GLM-5.3 系列；Claude Fable／Opus；DeepSeek-V4.1-Flash；经核实满足输入长度的 GPT 选项 | 来源对照、证据位置、结论与未决问题 |
| 看截图、图表、扫描材料 | 视觉输入支持、细节读取、文字定位 | 已核实接入支持视觉的 Claude、GLM-5.3-Flash、Kimi、DeepSeek-V4.1-Flash；其他已核实视觉模型 | 观察依据、图中位置及需要补充的材料 |
| 分类、提取、摘要等批量工作 | 结构化准确率、延迟、每项合格结果成本 | Claude Haiku；GPT-6 Luna；GLM 快速型号；DeepSeek-V4.1-Flash；其他经样例验证的可用型号 | 格式稳定、可抽查的结果 |
| 独立验收 | 理解规格、查证证据、发现反例 | 从能胜任该项目的模型中选择，必要时对高风险任务使用能力更强的候选 | 按验收条件逐项作出有证据的结论 |

文字流畅不能证明事实准确；模型写出的“测试通过”也不是测试证据。研究、数学、代码、图表等任务，各自仍需使用适当的资料、计算或运行结果核对。

## 9. 给 Concord 首次项目配置的使用建议

本节为配置引导提供选型背景；具体流程以 Skill 的建立与配置规则为准。当前通常推荐三个会话，包含首次配置聊天作为中控，不自动创建其他会话或更改模型。

首次配置模型时，先询问用户实际能使用哪些服务商、产品和型号，再了解项目需要完成什么、最关心质量还是速度／成本、是否有独立验收要求。已有明确选择直接采用，不要求用户先掌握所有模型名称。

可以用下面几种情况帮助用户选择，最后仍由用户决定角色、模型和实际会话：

| 项目情况 | 可以建议的分工 | 模型选择方式 |
| --- | --- | --- |
| 规模小、任务明确 | 一个执行角色，完成后自查 | 选择用户已有且能胜任的主力模型；自查不称独立验收 |
| 默认三会话，需要固定中控 | 中控、方案决策与验收、实现与验证 | 中控推荐 GPT-6 Luna 或其他能胜任调度的经济模型；关键方案由更适合复杂判断的模型负责 |
| 两会话协作，需要实现独立验收 | 方案决策与协调兼实现验收、实现与验证分别承担 | 关键方案交给更适合复杂判断的模型；执行者提出建议并自主落实常规细节；方案本身的独立复核另行安排 |
| 错误代价高、问题困难 | 复杂决策、实现、独立验收有明确责任 | 对困难环节使用合格候选，清晰的小任务按需选择快速模型 |

优先将关键方案、架构取舍和重大问题裁决交给候选中更适合复杂推理与判断的模型，执行模型调查后提出建议、实现并验证。方案决策者可以验收另一会话的实现，但不能把检查自己制定的方案称为方案独立复核。

模型品牌不同不保证意见独立，也不自动提高结果质量。同一模型在独立会话中也可以做独立复核；关键是职责、上下文、证据和验收标准。不要为了使用多个品牌增加无实际工作收益的角色。

每个实际绑定至少要分清：用户请求的模型、宿主能否核实实际模型、实际会话、负责范围。模型 ID 会被路由或应用会切换模型时，实际版本无法确认就写“未核实”，不能从角色名或回复风格推断。

## 10. 用自己的项目做一次小型比较

选择少量有代表性的真实任务，让候选使用相同输入和验收条件，再比较实际交付。没有必要先给所有模型做大而全的评分。

| 维度 | 应该记录什么 |
| --- | --- |
| 正确与完成度 | 是否满足验收条件，有无遗漏或事实错误 |
| 验证能力 | 是否真的运行检查、核对来源、检查输出 |
| 工具执行 | 是否能正确读取材料、修改文件、使用当前工具 |
| 返工 | 人工修正量、失败重试次数、是否需要升级 |
| 时间 | 从开始到结果可接受的总时间，而非仅输出速度 |
| 成本 | 有数据时记录输入、输出、缓存和重试费用；不可见时写未知 |

不要把订阅月费直接当作单次 API 成本，也不要只按每百万 token 单价比较。一个便宜模型若需要多次返工，总成本可能更高；一个能力更强的模型也可能对简单任务投入过多时间。并发数量沿用项目与用户的现有约束，本指南不另外设定。
