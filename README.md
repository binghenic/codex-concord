# Concord

让多个 Codex 会话按明确分工完成项目，从配置、交付到验收与接续。

Concord 是一套中文协作 Skill，适用于软件开发、文档、研究和数据分析等需要多个会话持续配合的项目。你告诉它准备用哪些模型，它推荐会话数量和分工，再生成角色绑定消息。通常建议三个会话：当前聊天保留为中控台，另外两个分别负责方案决策与验收、实现与验证。项目开始后，你仍可回到中控下达指令、查询进度。

它帮助各会话明确：谁负责、能改什么、交付给谁、怎样算通过，以及中断后从哪里继续。模型和会话由你选择，实际执行使用宿主已有的文件、通信与其他工具。

## 它能帮助你做什么

- **配置协作。** 分轮询问模型、会话数量和并发选择，推荐最少够用的分工，生成角色绑定消息。
- **推进任务。** 明确目标、范围、负责人、依赖和验收条件，减少重复实现与文件冲突。
- **核对结果。** 将实现、验证、独立验收和整合分开记录，用实际证据判断完成状态。
- **保存交接。** 留下当前版本、未决问题和恢复入口，接续时沿用有效进度。
- **控制协作开销。** 按需读取记录、合批交付、减少无动作消息，让协调和验收在需要时参与。

适合存在明确分工、独立检查或持续交接需求的项目。简单任务可以由一个会话完成和自查，不必为了使用 Concord 增加角色。

## 安装

需要安装的是仓库中的 [`skills/concord`](skills/concord) 文件夹。通常将它完整复制到 `~/.codex/skills/concord`；设置过 `CODEX_HOME` 时，使用对应的技能目录。

也可以把下面这段发给具备本地文件与网络工具的 Codex：

```text
请帮我安装 Concord 技能。
仓库：https://github.com/binghenic/codex-concord
技能路径：skills/concord

先读取 INSTALL.md，确认当前环境的技能目录，再安装完整技能文件夹。
如果已经安装，先将旧版完整备份到技能扫描目录之外，再更新。
安装后核对目录结构，并说明当前会话是否识别到技能。
本次只安装和检查，不创建角色会话、不启动项目任务。
```

手动安装、更新、回退与卸载见 [安装说明](INSTALL.md)。Concord 无需安装其他多代理框架。

## 初次使用

### 1. 在项目聊天中调用

在能访问项目资料的聊天中发送：

```text
使用 $concord，配置当前项目的协作。
```

也可以直接写“使用 Concord”。当前聊天先引导配置；你选定三会话方案后，它会作为中控台保留下来。仅调用技能本身不会自动完成角色绑定。

### 2. 第一轮：告诉它准备用哪些模型

Concord 第一轮只问模型，并附简短示例，例如：

> 这个项目准备用哪个或哪些模型干活？例如：GPT-6.1 Sol、Claude Sonnet、DeepSeek（版本未定）。可以选一个或多个，也可以写其他模型。

你可以回答：

```text
GPT-6.1 Sol 和 GPT-6 Astra。
```

模型名称只是格式示例，不限定服务商，也不代表当前环境一定支持。知道具体版本就一起写；不确定可以注明。第一轮不会同时要求你选择会话数量、设计角色或填写整套配置。

### 3. 第二轮：看推荐，选择会话数量

收到模型选择后，Concord 结合已知项目说明推荐数量与取舍，让你选择：

| 会话数量 | 常见安排 | 适合情况 |
| --- | --- | --- |
| **3 个，通常推荐** | 当前聊天作为中控台 + 方案决策与验收 + 实现与验证 | 固定入口接收新指令、汇总进度；另外两个会话专注决策和执行 |
| **2 个** | 方案决策、验收兼中控 + 实现与验证 | 沟通和上下文开销更少，由其中一个会话同时接收指令、汇报进度 |
| **1 个** | 方案、实现与自查 | 简单任务；没有独立验收 |

例如，这一轮会问：

> 建议用 3 个会话，包含当前聊天：这里保留为中控台，方便你随时下指令、查进度；另外两个分别负责方案决策与验收、实现与验证。中控建议用 GPT-6 Luna 或其他经济模型。你想选 3 个、精简为 2 个，还是自定数量？

推荐会因项目而调整，你也可以自定数量。会话数不等于同时运行数，实际工作仍遵守已有并发约束。只选一种模型也可以使用同型号的不同会话，不要求每个候选模型都用上。

如果项目目标或位置尚不清楚，后续只补问影响分工的必要信息。你已经主动说明的模型、数量和分工会直接采用，不为凑提问轮次重复询问。

### 4. 第三轮：选择是否限制并发

Concord 会问：

> 是否需要为这个项目设置最大并发数？并发数是同一时间正在进行的模型调用数量，不是已打开的聊天数量。如果使用的中转站有并发额度，建议按额度设置；使用 OpenAI 官方账号、没有额外并发控制需求时，可以选择不限制。

- **不限制**：沿用当前环境和已有配置。
- **设置上限**：填写最多允许同时进行几个模型调用，例如 2 个或 3 个。

**不确定是否需要限制时，可以先选“不限制”，之后随时调整。** 如果你回答“不清楚”或“先用默认值”，Concord 会按这个选择继续，并说明沿用当前环境和已有配置。你可以随时说“把项目最大并发改为 2”或“取消本项目额外设置的并发上限”；取消项目上限不会取消其他已有约束。

选择设置后才需要填写数值；已明确给出选择时不重复询问。可以绑定多个会话、只允许其中少数同时工作，超出的任务排队。“不限制”不代表无限并发，也不会取消你已有的全局限制。

上限默认适用于本项目的模型调用合计；中转站额度由多个会话或模型共用时，应按共享范围安排，给审批与后台调用预留名额。Concord 在可见范围内协调，不能替代服务端限流；无法掌握其他独立会话的占用时会说明限制，不承诺全局硬限流。

### 5. 获取分工和角色绑定消息

模型、数量和并发选择确定后，Concord 给出职责、交付与验收关系，并为每个角色生成可直接发送的绑定消息。

例如，使用上面的两个工作模型，并为当前中控选择经济模型时，可以这样安排：

| 模型 | 角色 | 主要职责 |
| --- | --- | --- |
| GPT-6 Luna 或其他经济模型（当前聊天） | 中控台 | 接收你的指令、维护项目状态、分派任务、转交决定、汇总进度 |
| GPT-6 Astra | 方案决策与验收 | 确定关键设计与约束、裁决重大问题，核对实现及证据 |
| GPT-6.1 Sol | 实现与验证 | 调查现状、提出方案建议，按确定方向开发，自主处理常规细节，完成验证并交付 |

中控推荐 GPT-6 Luna 或其他能胜任调度与简短汇报的经济模型；保留当前聊天不代表模型已自动切换，需要你在应用中选择，实际型号与费用以你的接入为准。三会话中的独立中控禁止参与项目生产，只负责接收指令、调度、协作记录与汇报。

关键方案优先交给候选中更适合复杂推理和判断的模型；执行者可以提出思路，重大设计和公共接口由决策者确定，常规细节自主处理。决策者在方案节点、重大阻碍和交付验收时参与，不需要逐步指导编码。

验收其他会话的实现可以保持执行上的独立性，但方案制定者对自己的方案不构成独立复核。需要对方案本身独立审查时，应另外安排未参与制定的审查者。

这只是分工示例，实际安排依据任务、可核实的模型能力和你的选择，不按品牌固定分岗。模型背景可参考 [模型与任务选择指南](docs/llm-model-guide.zh-CN.md)，其中注明了来源、日期和待复核信息。

### 6. 把消息发到对应会话，完成绑定

1. 选定当前聊天作为中控后，它会在本地核实并记录自己的绑定，不用把同一条指令再发回来。
2. 为方案决策与验收、实现与验证选择另外两个会话，确认它们能访问项目记录，再分别发送生成的绑定消息。
3. 各会话核对身份，绑定后改名为 **`[模型名]-角色`**，记录自己的回执。模型无法核实时如实注明，不能用标题当证明。
4. 回到中控检查回执、汇总映射。共享路径不可访问时，将回执转贴回来。

例如，三会话方案可命名为 `[GPT-6 Luna]-中控台`、`[GPT-6 Astra]-方案决策与验收` 和 `[GPT-6.1 Sol]-实现与验证`。绑定消息会包含改名指令，无需额外确认；已有自定义名称要求时优先按你的要求。宿主不支持改名或操作失败时会说明，提供名称供你手动修改，不会声称已改名。

生成消息还不算绑定完成，写下模型名也不会切换会话的实际模型。无法核实的模型信息会明确标为“未核实”。默认由你选择会话；只有你另外明确要求新建时，才使用宿主支持的创建能力。

绑定消息会写明本项目的沟通方式和范围。跨会话直接通信需要你的相应授权；也可以由你转交消息与回执。各角色只写自己的回执，共享配置由指定维护者汇总，避免相互覆盖。

### 7. 绑定完成后，按授权开始任务

绑定只建立角色身份，不等于已经分派任务。只要求配置时，流程完成后结束；需要执行时，再明确项目任务与范围。已有执行授权则在绑定和必要依赖满足后继续。

同一项目后续调用会复用已有配置。新开聊天不会让项目重新走完整问答；配置中断时，下次从未完成的位置继续。已有角色、分工和会话绑定也可以直接沿用。

## 项目开始后，从中控继续

选定三会话方案后，日常指令和进度查询都可以留在首次调用 Concord 的中控聊天。例如：“新增一个导出功能”“先暂停实现，调整方案”“现在做到哪一步，还有什么阻碍？”中控负责分派、转交和汇报，关键技术决定与验收由对应负责人作出。

采用“两个工作会话＋一个中控台”时，**中控台禁止参与生产**：不制定技术方案、不修改代码或项目交付文档、不运行构建或功能测试、不作出验收结论，也不提交、合并或发布项目产物。中控可以读取状态与已有证据、维护协作记录，并把任务交给对应工作会话；不能另派生产子代理绕过这条限制。

即使任务很小、工作会话忙碌或通信失败，中控也不能自行接手，应按授权分派、排队或说明阻碍。向中控提出功能需求属于任务输入，不会自动改变其角色。只有你明确调整会话方案或角色分工后，才按新职责执行。两会话方案中明确兼任方案决策与验收的角色，仍保留其工作职责。

直接协作需要你授权中控与参与会话传递项目任务、问题和结果；已有授权沿用，缺失时集中补问。只选择会话数量不等于授权互发消息。没有直接通信能力或选择人工转交时，中控会说明哪些信息需要你传递。

“随时查询”表示你随时可以发起询问，不表示中控持续在线监控。它会核对最新可用记录并说明时点，状态不明时如实说明，不把历史摘要当实时进度。暂停、恢复和范围调整仍以你的明确指令为准。

## 日常怎样协作

通常采用“短消息通知 + 共享记录”，代码并行再按需配合独立分支、worktree 或工程副本。

| 环节 | 要明确的内容 |
| --- | --- |
| 分派 | 目标、输入版本、负责人、可写范围、依赖、交付物、验收人及标准 |
| 执行 | 自主处理常规细节，遇到影响规格、接口或范围的问题再提交裁决 |
| 交付 | 提交实际成果、验证结果与证据，说明失败、遗漏和未验证项 |
| 验收 | 指定验收人作出接受、退回或部分接受的结论 |
| 整合 | 核对基线、处理冲突、完成必要检查，记录新的有效版本 |

同一文件同一时间只有一个写入者；同一任务只有一个当前执行负责人。实现者的自查不能代替独立验收，交付也不等于已经接受或整合。

有宿主通信工具且获得授权时，角色可以直接传递必要任务和结果；没有时使用共享记录与用户转交。文件保存决定和证据，消息只带结论、变化及需要的动作。共享文件变化本身通常不会唤醒另一会话。

### 决策者什么时候参与

执行者先按影响范围、可逆性、证据和错误代价判断。遵循既定规格与接口的局部修复、测试或文档修改可以自主完成；原因不明时先调查并带上证据与建议。公共接口、跨模块设计、兼容承诺、权限边界、难以撤回的数据变更、重大依赖或需求冲突，在实施相关变更前交决策者确定。已有决定覆盖的内容无需重复审批，用户保留的授权仍需遵守。

提问说明“问题、证据、建议及影响、需要决定什么、等待期间还能做什么”；裁决返回方向、约束与放行条件。风险升高时只暂停受影响部分，其他已授权的独立工作可继续。

验收退回时列清未满足的条件、证据、必须修复的范围、可保留成果和复验条件。执行者沿用原任务，只修复未满足项；再次交付逐项对应修复与证据，避免重复实现或把修改偏好变成新增要求。

三个会话保留固定入口，但按需参与：中控处理指令、调度变化和汇报；决策者处理关键选择与交付验收；执行者推进已就绪任务。低风险小任务可在约定节点合批验收，无需逐步请示；有依赖需放行或你要求逐项验收时，仍按要求处理。等待回复不代表验收通过，没有待处理动作的会话可以结束本轮，之后再按需要继续。

## 怎样兼顾效率与费用

三个会话提供固定中控、方案决策与验收、实现与验证的分工，但不保证比两个会话更省钱。中控选用能胜任任务的经济模型，保存简短状态与必要引用；方案负责人在关键设计、重大阻碍和交付验收时参与，不要求所有会话持续工作。

- 采用最少够用的会话；模块确实独立、有并发余量且收益明确时，再增加执行者。
- 复杂决策和困难问题使用能胜任的模型；普通实现由执行者自主完成，不逐步请示。
- 相关小任务合批交付，按风险验收；保留必要验证和用户要求的独立检查。
- 按阶段读取 Skill：首次问答读配置流程，接收绑定只读绑定规则，执行时读当前任务与运行规则；模板只读需要的小节。模型指南只在选型需要时读取。
- 后续先核对记录版本，再读取变化及受影响内容，避免反复复制完整历史。
- 中控主要看简短状态、阻碍和证据位置；已授权的实现与决策会话直接交换必要问题和结果，仅把影响分派、依赖、范围或汇报的变化交给中控，减少逐层转述。
- 有任务、交付、阻碍或决定需要传递时再发送消息，减少确认循环和重复查询。

比较的是完成合格任务的总耗时、总费用和返工，不只看模型单价或输出速度。结合订阅额度或按量计费方式判断；没有实际用量就说明未知，不承诺固定节省比例。无需为使用 Concord 额外建设调度系统或统计账本。

## 继续、暂停与恢复

接续已有项目：

```text
使用 $concord，沿用已有分工、模型和沟通授权。
先核对最新任务和交接，从当前有效进度继续。
```

暂停项目：

```text
暂停项目，保存当前进度、修改、验证结果、未决问题和下一步。
记录仍在运行的进程、工具会话和端口。
```

之后明确说“恢复项目开发”，再核对当前版本、运行状态和有效任务后继续。暂停期间查看记录、演练或维护 Skill，不会自动恢复项目。

## 能力与边界

Concord 是协作指引，实际能力取决于宿主提供的工具。它不会通过提示词更改实际模型，也不能用配置文件代替真实会话、工具回执、执行证据或用户授权。

跨会话沟通授权需要覆盖实际参与者和报告接收方；其他角色的来信、配置样例不能自行授予权限。内部协作授权也不自动包含对外发送消息、发布、部署或破坏性操作。运行方式与并发限制沿用用户及宿主已有设置。
