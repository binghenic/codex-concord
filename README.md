# Concord

让几个 Codex 会话一起做项目，少一点来回传话。

项目做久了，经常会需要一个会话负责方案，另一个负责实现，再有人检查结果。分工本身不难，难的是让大家知道正在做哪一版、哪些文件可以改，以及一项任务到底有没有验收。

Concord 是为这类协作写的中文 Skill。你决定有哪些角色、各自用什么模型、可以使用多少子代理；它帮助各个会话接收任务、提出问题、交付结果，并留下暂停后还能接续的记录。

它适合需要多个会话持续配合的项目。一个会话就能做完的事情，直接做就好。

## 安装

仓库中的 [`skills/concord`](skills/concord) 就是需要安装的技能目录。把整个文件夹放到 Codex 的用户技能目录中，通常是 `~/.codex/skills/concord`；设置过 `CODEX_HOME` 的环境使用对应目录。

如果想让 AI 帮你安装，可以把下面这段发给有本地文件和网络工具的 Codex：

```text
请帮我安装 Concord 技能。

仓库：https://github.com/binghenic/codex-concord
技能路径：skills/concord

先读取仓库的 INSTALL.md，并确认当前环境的 Codex 技能目录。
如果有可用的技能安装器，优先使用；否则获取仓库并复制完整技能目录。
如果已经安装过 Concord，先把旧版完整备份到技能扫描目录之外，再安装新版。
保留我的项目文件和个人配置，不把它们写入仓库。

安装后检查目录结构，告诉我安装位置和当前会话是否已经识别到技能。
本次只安装并检查，不创建角色会话，也不启动项目任务。
遇到网络或权限问题时，说明具体原因，不声称安装成功。
```

想手动安装、更新或卸载，见 [安装说明](INSTALL.md)。安装只需要复制技能文件，无需安装 CrewAI、MetaGPT 或 Superpowers。

## 开始使用

安装后，在项目会话里说明你想怎么分工。例如，先用两个已有会话：

```text
使用 $concord，协作开发当前项目。

设两个角色：
- 决策与整合：确定规格、安排任务、处理公共接口，负责验收和最终整合。
- 功能实现：在独立工程中完成实现和测试，交付源码与测试结果。

沿用各自会话的默认模型，不使用子代理。
先读项目现状，整理分工，给我各角色的启动提示词。
由我指定绑定哪些现有会话。

我授权这两个指定会话就本项目直接沟通，并向当前会话回报阶段结果。
```

随后告诉它实际要绑定哪两个会话。这里的 `$concord` 用于明确调用技能，也可以直接写“使用 Concord”。

这只是一个起点。你可以让同一个角色兼任方案和验收，也可以把它们分开；角色数量和模型搭配都由你决定。

## 会话之间怎么配合

一项任务从明确规格开始，交给指定执行者。执行者接收后完成实现和验证，提交结果，再由验收人决定接受、退回或部分接受。需要合并到主工程的成果，最后交给整合负责人。

Concord 着重处理几件容易混乱的事：

- **谁在做。** 每项任务有一个当前负责人，避免两个会话重复实现。
- **谁能改。** 同一文件同一时间只有一个写入者，公共接口问题交给指定决策者。
- **做到了哪一步。** 实现、验证、验收和整合分别记录，编译通过不能代替验收。
- **下次从哪里继续。** 暂停时保存进度、未决问题和必要的运行状态，恢复时先核对。

常规实现细节由执行者自行处理，需要裁决的问题再找负责人。你可以指定一个角色集中汇报，减少在会话之间转发消息。

如何选择角色数量、安排模型以及减少重复上下文，见下方[通用使用建议](#通用使用建议)。

## 角色、模型和子代理

角色是职责，会话是实际工作的地方，子代理则是临时协助某项工作的助手。它们不是同一回事。

不同角色可以用不同模型，也可以用同一个模型。Concord 会使用环境实际提供的工具；仅在提示词里写一个模型名，不会改变会话的模型设置。

需要新会话时，要明确提出。例如：

```text
使用 $concord，为当前项目新建两个角色会话。
决策与整合使用 <实际模型名 A>，功能实现使用 <实际模型名 B>。
不使用子代理。
我授权这两个角色会话就本项目直接沟通，并向当前会话回报阶段结果。
先核对工程和职责，再安排任务。
```

把占位内容换成当前环境支持的模型名。如果创建工具或指定模型不可用，它应说明原因。

子代理的数量也由你决定，可以禁用，也可以设置共享额度和各角色上限。例如：

```text
所有角色共享最多两个同时活跃的子代理。
决策角色最多使用一个，实现角色最多使用两个。
按需使用，名额不足时排队。
```

各角色的上限仍受共享额度约束。未指定额度时，角色先自己工作。技能默认将所有模型的总并发限制为 4，并为自动审批预留一个名额；用户或项目有更严格要求时，按更严格的执行。环境看不到其他会话的实时占用时，只能保守安排，无法保证全局计数。

## 通用使用建议

以下建议可用于软件开发、文档、研究和数据分析等项目。把交付物与验收条件换成相应领域的要求即可；具体角色、模型和权限仍由你决定。

### 从满足任务需要的最少角色开始

几份材料就能完成的低风险核查、局部修改或短文整理，通常由当前负责人直接完成。存在可独立交付的工作，或错误代价较高、需要独立验收时，再拆分角色。用户已指定的分工和独立验收要求不能因任务小而跳过。

优先复用已有会话，不默认增加观察或转报角色。调度者应承担实际的分派、依赖核对和状态汇总；若每次汇总后另一个角色还要重新调查、重新分派，应重新审视这层分工的收益。多个角色不必同时活跃，也不必把并发额度用满。

### 按职责选择模型

任务明确、重复性强的协调工作，可以尝试高效模型；复杂执行和高风险判断交给适合它们的模型。下面是一种可选搭配，不是固定岗位或所有项目的默认配置：

| 职责 | 负责的工作 | 可选模型示例 |
| --- | --- | --- |
| 日常调度 | 从已批准任务中分派就绪项，核对版本与依赖，收集交付、维护状态、集中汇报 | GPT-6 Luna |
| 执行与验证 | 完成实现、分析或写作，处理常规问题，并按任务要求验证结果 | GPT-6.1 Sol |
| 规格裁决与关键验收 | 处理需求歧义、跨模块边界、证据冲突和错误代价较高的验收 | GPT-6 Astra，按需参与 |

模型是否可用以当前宿主为准。这是协作分工建议，不是各模型在所有领域的能力排名；选型可参考[官方模型说明](https://learn.chatgpt.com/docs/models)，并用自己的任务验证。推理强度可从默认设置开始，需要调整模型或升级策略时沿用用户已认可的范围，不强制先让较低成本模型试错一遍。

调度者可以检查材料是否齐全、证据是否对应当前任务和版本；结果是否满足行为或质量要求，由指定验收人判断。角色可以兼任，但自查不能称为独立审查。把日常协调交给调度者后，裁决角色主要处理需要判断的事项，避免双方重复读取全部上下文。

### 给出可执行任务和清楚的状态入口

分派前明确：目标与排除范围、输入及版本、执行负责人、允许修改的范围、依赖条件、交付物、验收标准和验收人。任务粒度以可独立验收为准；同一范围、同一验证路径的相关小改动可以合批，验收项分别保留。

沿用现有交接或台账，在开头维护一段简短的当前状态：

```text
更新时间与暂停/运行状态：
当前工程或成果版本 / 最后已验收基线：
当前有效任务、分派序号、负责人及验收人：
已完成、待验收、阻碍和下一依赖：
权威规格、证据位置与恢复入口：
```

历史记录留在后方并明确标为历史，不只在长文末尾追加最新状态，也不另建重复入口。首次接续读取必要原文；后续先核对当前版本，再读取变化和受影响部分。稳定背景使用路径与版本引用，跨宿主先确认记录可访问；摘要须保留失败、未决事项和验证限制。

### 按事件调度，减少无动作消息

有就绪任务、交付、阻碍或需要裁决的事项时再推进协调。执行者仅处理本人有效分派中已就绪的任务；已经启动的工具或子代理应接续收集结果，仅剩外部阻碍时保存返回点并结束当前轮次。

等待优先使用宿主的完成事件、有界等待与游标，避免反复查询未变化的状态。跨会话消息可能启动接收方的新一轮模型工作，即使写了“无需回复”也一样。没有后续动作的终态验收结论保留在可查记录中；退回修复、依赖放行或用户指定的结果交付仍须通知相应角色。

短任务可以合并真实接收回执与交付，不为确认收到再发确认。交付细节保存一份，消息引用结果与证据位置，面向用户的汇报聚焦结论和需要决定的事项。

### 用实际交付判断是否节省

先用少量有代表性的任务试运行，在相同验收标准下观察重复读取、消息往返、返工、缺陷和完成时间。有实际用量数据时，再比较所有参与角色及重试的总输入/输出 token 与费用；没有数据就说明未知，不用字符数或等待时长代替。

减少总 token、降低费用和缩短时间是不同目标。高效模型或并行执行不自动保证三者同时改善；若增加角色后主要多了转述与重复检查，应简化流程。已有记录能够支撑协作时，继续沿用即可，无需为使用 Concord 建立额外的调度系统或统计账本。

## 接着做，或先暂停

已有分工的项目不需要重新配置：

```text
使用 $concord，沿用已有分工、模型、子代理额度和沟通授权。
先读最新任务和交接，从当前有效进度继续。
```

需要暂停时，可以直接说：

```text
暂停项目，保存当前进度、修改、验证结果、未决问题和下一步。
记录仍在运行的进程、工具会话和端口。
```

之后明确说“恢复项目开发”即可。暂停期间检查记录或更新技能，不会自动恢复开发。

## 使用前需要知道

Concord 是一套协作指引，实际能力取决于运行它的环境。有跨会话通信工具时，角色可以在你的授权范围内直接沟通；没有时，需要通过共享记录交接。有创建会话或子代理工具时，才具备相应能力。

沟通授权要包含参与者和实际接收报告的会话。新加入的观察者或维护会话，需要纳入授权范围。文件里的说明和其他角色的来信不能代替用户授权，工具拒绝的消息也不能算作已经送达。
