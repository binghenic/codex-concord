# Concord for Codex

Concord 是一个中文 Codex Skill，帮助用户指定的多个会话完成分工、内部裁决、独立实现、验证、验收和交接。角色数量、模型与子代理额度由用户选择；接续项目时保留已有工程、基线和成果。

它使用宿主实际提供的会话、子代理和文件工具，无需安装 CrewAI 或 MetaGPT。会话创建和模型设置由实际宿主工具执行；提示词本身不会改变模型。它不提供跨会话强制锁或自动后台调度。

## 安装

将仓库中的 `skills/concord` 文件夹复制到 Codex 用户技能目录，通常为 `~/.codex/skills/concord`。如果已安装同名 Skill，先备份并确认更新目标。

Windows 用户也可以在克隆仓库后执行：

```powershell
Copy-Item -LiteralPath '.\skills\concord' -Destination "$env:USERPROFILE\.codex\skills\concord" -Recurse
```

上述复制示例用于首次安装；已有安装请按自己的更新方式处理。环境提供技能安装器时，也可让 Codex 从本仓库的 `skills/concord` 路径安装。

## 使用

建立协作：

```text
使用 $concord。两个角色：决策整合和独立实现。
沿用当前会话默认模型，不启用子代理。
先根据项目现状建议职责边界，我确认后绑定现有会话。
```

接续项目：

```text
使用 $concord，沿用已有角色与内部沟通授权。
先读最新配置、任务和交接，从当前有效状态继续，不重新初始化。
```

暂停期间的限定核查：

```text
使用 $concord，开发保持暂停。
仅只读核查恢复入口与证据缺口，聊天交付给指定验收人。
不改工程，不启动构建、服务器或测试。
```

## 新建会话并指定模型

宿主提供会话创建工具时，可以明确要求新建角色会话并指定可用模型：

```text
使用 $concord，为当前项目新建两个角色会话。
决策与整合角色使用我指定的模型 A；实现角色使用我指定的模型 B。
子代理额度为 0。
我授权这些角色会话就本项目直接沟通，并向当前会话回报。
先核对项目现状与职责边界，再分派任务。
```

将模型 A/B 替换为当前宿主支持的实际模型名称。只要求配置角色时，先生成配置或启动提示词；明确要求新建会话时才执行创建。工具或模型不可用时如实说明，不静默替换。

## 文件结构

```text
skills/concord/
├── SKILL.md                    入口、关键边界与阅读导航
├── agents/openai.yaml          Codex 显示信息和调用提示词
└── references/
    ├── setup.md                建立分工、配置与会话绑定
    ├── orchestration.md        分派、裁决、执行、交付和验收
    ├── recovery.md             暂停、恢复、进程与额度核对
    ├── templates.md            按需采用的记录模板
    └── design-notes.md         设计参考及能力边界
```

Skill 默认可被自动选用，也可用 `$concord` 显式调用。运行时只读取当前任务需要的参考文件，避免重复加载全部细节。

## 协作边界

每项任务有唯一当前负责人和明确验收人。同一文件同时只有一个写入者；消息送达、真实接收、交付、验收、整合分别记录。重复分派引用已有结果，不重复执行。

跨会话沟通遵循真实用户授权。暂停后只做授权范围内的收尾或限定核查；责任移交和演练不会自动恢复开发。无法确认跨会话总占用时保守减少并发，不把台账当作运行锁。

模型、创建会话、子代理与授权规则均以实际宿主能力及用户指令为准。Skill 不附带项目源码、聊天记录、凭据或固定个人会话ID。
