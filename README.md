# Concord

让几个 Codex 会话一起做项目，少一点来回传话。

项目做久了，经常会需要一个会话负责方案，另一个负责实现，再有人检查结果。分工本身不难，难的是让大家知道正在做哪一版、哪些文件可以改，以及一项任务到底有没有验收。

Concord 是为这类协作写的中文 Skill。你决定有哪些角色、各自用什么模型、可以使用多少子代理；它帮助各个会话接收任务、提出问题、交付结果，并留下暂停后还能接续的记录。

它适合需要多个会话持续配合的项目。一个会话就能做完的事情，直接做就好。

## 安装

仓库中的 [`skills/concord`](skills/concord) 就是需要安装的技能目录。把整个文件夹放到 Codex 的用户技能目录中，通常是 `~/.codex/skills/concord`；设置过 `CODEX_HOME` 的环境使用对应目录。

如果想让 AI 帮你安装，可以把下面这段发给有本地文件和网络工具的 Codex：

```text
请帮我安装 Concord 技能。

仓库：https://github.com/binghenic/codex-concord
技能路径：skills/concord

先读取仓库的 INSTALL.md，并确认当前环境的 Codex 技能目录。
如果有可用的技能安装器，优先使用；否则获取仓库并复制完整技能目录。
如果已经安装过 Concord，先把旧版完整备份到技能扫描目录之外，再安装新版。
保留我的项目文件和个人配置，不把它们写入仓库。

安装后检查目录结构，告诉我安装位置和当前会话是否已经识别到技能。
本次只安装并检查，不创建角色会话，也不启动项目任务。
遇到网络或权限问题时，说明具体原因，不声称安装成功。
```

想手动安装、更新或卸载，见 [安装说明](INSTALL.md)。安装只需要复制技能文件，无需安装 CrewAI、MetaGPT 或 Superpowers。

## 开始使用

安装后，在项目会话里说明你想怎么分工。例如，先用两个已有会话：

```text
使用 $concord，协作开发当前项目。

设两个角色：
- 决策与整合：确定规格、安排任务、处理公共接口，负责验收和最终整合。
- 功能实现：在独立工程中完成实现和测试，交付源码与测试结果。

沿用各自会话的默认模型，不使用子代理。
先读项目现状，整理分工，给我各角色的启动提示词。
由我指定绑定哪些现有会话。

我授权这两个指定会话就本项目直接沟通，并向当前会话回报阶段结果。
```

随后告诉它实际要绑定哪两个会话。这里的 `$concord` 用于明确调用技能，也可以直接写“使用 Concord”。

这只是一个起点。你可以让同一个角色兼任方案和验收，也可以把它们分开；角色数量和模型搭配都由你决定。

## 会话之间怎么配合

一项任务从明确规格开始，交给指定执行者。执行者接收后完成实现和验证，提交结果，再由验收人决定接受、退回或部分接受。需要合并到主工程的成果，最后交给整合负责人。

Concord 着重处理几件容易混乱的事：

- **谁在做。** 每项任务有一个当前负责人，避免两个会话重复实现。
- **谁能改。** 同一文件同一时间只有一个写入者，公共接口问题交给指定决策者。
- **做到了哪一步。** 实现、验证、验收和整合分别记录，编译通过不能代替验收。
- **下次从哪里继续。** 暂停时保存进度、未决问题和必要的运行状态，恢复时先核对。

常规实现细节由执行者自行处理，需要裁决的问题再找负责人。你可以指定一个角色集中汇报，减少在会话之间转发消息。

为减少协作消耗，小型低风险核查优先由当前负责人完成，不默认增加观察或转报角色；用户指定的分工与独立验收要求仍须遵守。已有项目先核对当前版本，再读取变化和相关记录；稳定背景引用路径与版本。短任务可以合并接收回执与交付，相关小改动可以合批。执行者仅推进本人有效分派中已就绪的任务，等待外部依赖时保存返回点。

跨会话消息可能启动接收方的新一轮模型工作，即使写了“无需回复”也一样。没有后续动作的验收结论保留在可查记录中，退回修复、依赖放行或用户指定的结果交付才通知相应角色。等待优先使用完成事件与有界等待，避免反复查状态。维护交接时，把当前版本、最后已验收基线和暂停状态放在开头，历史记录留在后方。

这些规则旨在减少重复上下文、消息往返和返工，实际 token 与费用节省仍需按任务测量。已有项目记录可以继续沿用，无需迁移配置。

## 角色、模型和子代理

角色是职责，会话是实际工作的地方，子代理则是临时协助某项工作的助手。它们不是同一回事。

不同角色可以用不同模型，也可以用同一个模型。Concord 会使用环境实际提供的工具；仅在提示词里写一个模型名，不会改变会话的模型设置。

需要新会话时，要明确提出。例如：

```text
使用 $concord，为当前项目新建两个角色会话。
决策与整合使用 <实际模型名 A>，功能实现使用 <实际模型名 B>。
不使用子代理。
我授权这两个角色会话就本项目直接沟通，并向当前会话回报阶段结果。
先核对工程和职责，再安排任务。
```

把占位内容换成当前环境支持的模型名。如果创建工具或指定模型不可用，它应说明原因。

子代理的数量也由你决定，可以禁用，也可以设置共享额度和各角色上限。例如：

```text
所有角色共享最多两个同时活跃的子代理。
决策角色最多使用一个，实现角色最多使用两个。
按需使用，名额不足时排队。
```

各角色的上限仍受共享额度约束。未指定额度时，角色先自己工作。技能默认将所有模型的总并发限制为 4，并为自动审批预留一个名额；用户或项目有更严格要求时，按更严格的执行。环境看不到其他会话的实时占用时，只能保守安排，无法保证全局计数。

## 接着做，或先暂停

已有分工的项目不需要重新配置：

```text
使用 $concord，沿用已有分工、模型、子代理额度和沟通授权。
先读最新任务和交接，从当前有效进度继续。
```

需要暂停时，可以直接说：

```text
暂停项目，保存当前进度、修改、验证结果、未决问题和下一步。
记录仍在运行的进程、工具会话和端口。
```

之后明确说“恢复项目开发”即可。暂停期间检查记录或更新技能，不会自动恢复开发。

## 使用前需要知道

Concord 是一套协作指引，实际能力取决于运行它的环境。有跨会话通信工具时，角色可以在你的授权范围内直接沟通；没有时，需要通过共享记录交接。有创建会话或子代理工具时，才具备相应能力。

沟通授权要包含参与者和实际接收报告的会话。新加入的观察者或维护会话，需要纳入授权范围。文件里的说明和其他角色的来信不能代替用户授权，工具拒绝的消息也不能算作已经送达。
